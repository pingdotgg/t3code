# End-to-end orchestrator run, 2026-11-20

One real goal ran through the board UI at `main` (`04f9b679e1`) against an isolated T3 0.1.10 engine. The orchestrator was Claude `claude-opus-5-5` at medium. A scratch Node package was pushed to a throwaway private repo, and CI ran on a local self-hosted runner after GitHub refused hosted runners for billing.

The goal, typed verbatim into the orchestrator chat:

> Add a `slugify(text)` function to slugkit with unit tests. Then add a `bin/slug` CLI that uses it, with a test. Then document both in the README. Open a PR for each change against main, and ask me before merging anything.

The run took 21.5 minutes from the goal to the last merge. The orchestrator started 19 agents and merged three PRs after three approvals.

No failure sat in the board UI or its data layer, and none sat in the coordination store. Child wakeups, the builder cap, and approval gating all held. Building a stacked child while its parent is in review matches the stack workflow, which enforces order at merge, so check 4's rule was stricter than the workflow this board replicates.

The test driver answered the orchestrator's first three CI questions with a false option, "billing fixed". That cost about 5 minutes of re-runs and did not change order, concurrency, roles, or the reload.

# Skill feed probe

A probe on 2026-11-20 tested how an orchestrator can keep its rules, and what Claude Code's built-in subagent tool does under T3. It ran on an isolated T3 0.1.10 engine with Claude Code 2.1.309 and `claude-opus-5-5` at medium effort. Each run started a thread through T3's own launch call and read the result back from T3's projection. A canary is a made-up string that only one place holds, such as `PLUM-4471`, so asking for it shows whether that place survived.

## Results

| Question                                                    | Result                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Does text in an appended system prompt survive `/compact`?  | Yes, 10 of 10 runs. The instance's launch arguments held `--append-system-prompt-file <path>`, and every post-compact answer gave the canary. Claude Code sends that text with every request, so the summary never has to carry it.                                                                                                                                                                                                                                     |
| Does text only in the first message survive `/compact`?     | In short chats, yes, 4 of 4. In a long session, no. With the board's real 14.8 KB brief, a goal turn, and a scout, the summary dropped the canary 2 of 2 times. The model still answered it 2 of 2 times, but only because the summary names the old transcript file and the model searched it with a shell command. That works only while the file exists and the model thinks to look, so it is no basis for standing rules.                                          |
| Does a `$skill` survive `/compact`?                         | Yes, 4 of 4 short chats. The summary kept the canary, and Claude Code attached the skill text again after the summary. It was not tested inside a long session.                                                                                                                                                                                                                                                                                                         |
| Does `--disallowedTools` remove the built-in subagent tool? | Yes. `--disallowedTools "Task,Agent"` and `--disallowedTools Task Agent` both removed `Task` from the tool list Claude Code gave the session, where the unflagged runs had it. T3 splits the launch arguments and passes unknown flags to Claude Code as extra arguments, in `ClaudeAdapterV2.ts` lines 2225 to 2244, so it has no handling of its own for this flag. In Claude Code 2.1.309 the tool is named `Task` in the tool list, and the model calls it `Agent`. |
| What happens to a built-in subagent call without the flag?  | T3 makes a child thread from it. In a forced test the child was titled `hello`, with `creationSource` `provider` and `relationshipToParent` `subagent`, beside the `delegate_task` child whose `creationSource` is `mcp`. The board showed it as an unassigned card, with no registry role behind it.                                                                                                                                                                   |
| What happens with the flag?                                 | The model cannot call a tool that was not loaded. Asked to call it, the model searched for it and got `No matching deferred tools found`, and no child thread appeared.                                                                                                                                                                                                                                                                                                 |

## What this changes

- Standing rules go in the instance's launch arguments as an appended system prompt, so they survive every compaction. The first message holds only what differs between boards.
- The orchestrator's instance also disallows `Task` and `Agent`, so every agent it starts comes from `delegate_task` and has a registry role.
- A child that T3 made from a provider subagent call, on an instance that lacks the flag, is flagged on its card.

## Limits

- Each cell above ran 2 to 10 times, and compaction summaries are model-written, so a count is a measurement and not a rate.
- The long-session counts describe the board's brief at that time with one goal, so they say a first message can be lost and not how often.
- Evidence: the transcripts and tool lists from the probe are in `/tmp/skill-probe/evidence/` on the machine that ran it, as `q4-compaction.txt`, `q5-disallowed-builtin.txt`, `tools-list-by-arm.txt`, `force-q1.txt`, and `q1-family-after-forced-builtin.txt`.

# Developer-preview extension placements

The web/desktop shell supports generic registered views in `side-panel` and `bottom-dock`. `openExtension(threadRef, record)` routes the copied record to the selected container. `full-page` and `compact-detail` are SDK metadata values reserved for other host implementations; this shell refuses new opens at those placements. The native repository PR page and Terminal dock keep their existing dedicated integrations. A right-panel contribution is not a new destination in the main navigation sidebar.

Each viewer is owned by its layout environment/thread, placement, and contribution/resource identity. A project-scoped resource can have separate saved views in two threads. Explicitly opening the same resource in the right panel and extension dock creates two independent viewers; it does not move a viewer or promise shared React state. Domain-resource sharing belongs to the trusted host service adapter.

The extension dock has independently selectable views and its own layout toggle. Hiding deactivates the selected SDK view and keeps its mounted state; showing restores it without changing native Terminal state. Switching tabs or threads can dispose and restore a view from its saved record. Closing removes that saved viewer; an explicit later open uses the record supplied by its producer. Saving a record never focuses a view, opens a hidden container, advances the user's layout-choice revision, or resurrects a closed viewer.

Both containers share the existing 64-view per-thread bound. Layout storage version13 moves valid legacy bottom-dock records out of the right-panel list and preserves their saved state. Valid legacy full-page/compact-detail entries retain an unavailable placeholder and close control in their historical location, without activating a renderer in the wrong placement. Unknown contributions at supported placements retain their usual fallback until registered. Hydration validates both maps, deduplicates within each placement and preserves thread scope.

The dock uses the existing shell animation settings, deactivating extension activity at the start of hide and retaining only presentation through the exit. A cold hidden record does not activate before it is shown. The dock frame's height is host-owned geometry: the user drags its top edge (bounded, persisted per thread) and the SDK supplies no plugin-declared or plugin-driven sizing. A surface's contract is to size its own content to the frame it is given — including terminal views, which fit their rows to the current frame rather than negotiating dock geometry. React Native mobile does not consume this web layout implementation.

Contributor validation should exercise a public counter in both placements and two threads, save/reload, hide/show, close, unregister/re-register, malformed/unsupported restore, and a real native Terminal open alongside the dock. Confirm readable geometry and keyboard controls at a small viewport. The component regression includes a native-dock sibling lifetime probe; it does not replace real PTY, compositor, backend-resource or performance measurements.

Explicit open replaces the app viewer generation, including when the resource identity is unchanged. Background saves carry their captured generation and may change only restore state when immutable record metadata still matches. Hydration discards the runtime generation; an old hydrated viewer cannot save after a fresh explicit open. Hiding retains only the last visibly selected viewer; closing it while hidden does not activate a cold successor.

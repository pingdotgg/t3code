# T3 Code and Auldric Marketing

T3 Code remains the coding environment. When Auldric Marketing is enabled, it appears as a separate
Marketing and Strategy workspace behind an explicit Marketing entry point.

## What stays T3 Code

The Dev workspace, coding conversations, providers, Settings, terminal, source control, diff,
preview, pairing, remote connections, updates, and diagnostics keep the T3 Code name and behavior.
Returning to Dev also removes Marketing instructions and evidence from later coding turns.

## What is Auldric

Inside Marketing, Auldric owns the source library, Day 0 consultation, Marketing Strategy and GTM
workflows, saved artifacts, revisions, evidence, decisions, reviews, and approved briefs handed to
Dev. Auldric branding appears only in those Marketing surfaces and in Auldric's own public pages.

An approved brief does not rename or take control of Dev. It gives the T3 coding agent a bounded,
reviewed input, and the user still decides whether to execute it.

## Separate application installs

If an Auldric desktop application is distributed separately, it installs beside T3 Code. It has a
different application identity, launch link, update feed, and local data directory. Installing,
updating, downgrading, or removing Auldric does not replace or migrate a T3 Code installation.

The current T3 Code mobile application remains a T3 remote client. An Auldric-branded mobile app is
not distributed until it has its own application, signing, update, and store identities.

## Recognizing the boundary

- **T3 Code** labels mean coding or shared runtime capability.
- **Auldric** labels mean an explicitly entered Marketing/Strategy capability.
- If Marketing is unavailable, Dev still opens and works as T3 Code.
- If a screen mixes the identities or a Marketing turn affects a later Dev turn, treat it as a
  product-boundary defect.

Maintainer-level identifier, compatibility, migration, and rollback rules are in the
[identifier ownership matrix](../internals/identifier-ownership.md).

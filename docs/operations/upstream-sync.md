# Syncing upstream T3 Code

Ada merges `upstream` (pingdotgg/t3code) into `main` regularly. Upstream keeps changing features Ada removed on purpose, so a sync that takes "theirs" brings them back. This page lists those removals and how to keep them out. The release side of a sync is in [Community fork releases](fork-releases.md).

## How to sync

- **Merge, never rebase.** `git fetch upstream && git merge upstream/main` on a `sync/upstream-<date>` branch from `origin/main`, then a normal PR. `main` blocks force-pushes, and a merge keeps every fork commit and conflict resolution reviewable.
- **Keep upstream migration ids.** Effect matches migrations by id, so renumbering one makes Ada and T3 Code databases incompatible. Take upstream's new `apps/server/src/persistence/Migrations/NNN_*.ts` at their ids, put fork migrations only under `Migrations/fork/`, and run `node scripts/check-upstream-migrations.ts --sync upstream/main`. Keep upstream migrations for removed features (such as `090_AuthConnectDevices`); existing databases have run them.
- **Keep fork workflows.** The `fork-*` workflows, `release-desktop.yml`'s fork repository and signing inputs, and `.github/triage/` stay Ada's. Take upstream's job fixes, not its repository names, hosts or release targets.
- **Keep fork fixes.** `node scripts/check-fork-guards.ts --base origin/main` names the fork fixes whose files the merge touched; re-check each.

## Check for leftovers

`vp run check:changed` runs `scripts/check-removed-connect.ts`, which fails on a returned manifest path, a banned dependency, an `@clerk/` import, or an upstream analytics host or hosted app in shipped code. `scripts/upstream-install-commands.test.ts` catches upstream install commands. Grep for what they miss:

```sh
git diff --name-only origin/main...HEAD | grep -iE 'relay|cloud|clerk|posthog|telemetry|sentry|sourcemap|guest|legal|privacy|security'
git grep -nIiE 'posthog|clerk|cloudLink|relayClient|guestShare|T3 Connect|app\.t3\.codes|pingdotgg|compactContext|hasCompactableConversation' -- apps packages ':!*.test.*' ':!**/fixtures/**'
git grep -nI 'T3 Code' -- apps/web/src apps/mobile/src docs/user
```

Hits that remain on purpose are the compatibility shims above, `.github` workflow guards that check `github.repository`, generated schemas and test fixtures. Justify any other hit in the sync PR.

`AWS.Website.SolidStart` deploys a
[SolidStart](https://start.solidjs.com) app to AWS. It runs your
project's own `vite build` and appends nitro's `node` preset: the SSR
server runs on a [Lambda Web Function](/aws/compute/web-functions) and
streams its responses, and client assets plus prerendered pages are
served from a private S3 bucket through CloudFront. A CloudFront
Function routes each request at the edge — uploaded files go to S3,
everything else streams from the server.

:::note[Verified version line]
This page tracks `@solidjs/start` **2.x** with
`@solidjs/vite-plugin-nitro-2` — the Vite-native line where
`solidStart()` is a plain Vite plugin and nitro is a second plugin.
:::

## Install

The build integration is not bundled with alchemy. Install
`@alchemy.run/frontend-frameworks`; the resource loads its
`/solidstart` and `/solidstart/node` exports from your project at
deploy time. It is only used at build time, so a dev dependency is
enough:

<PackageManagers dev={devDeps} />

`@solidjs/vite-plugin-nitro-2` is the server half of a SolidStart
build and must be a project dependency too:

<PackageManagers add="@solidjs/vite-plugin-nitro-2" />

## Configure Vite

Your `vite.config.ts` is just the SolidStart plugin — no adapter, no
nitro wiring:

```typescript
// vite.config.ts
import { solidStart } from "@solidjs/start/config";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [solidStart()],
});
```

Alchemy appends its own `nitroV2Plugin()` instance at build time,
carrying nitro's `node` preset (`aws-lambda`, streaming enabled, with
`server: "function"`).
Don't register `nitroV2Plugin()` yourself — the appended instance
would discard its options, so the build fails with an actionable
error instead. Pass nitro options through the resource's `nitro`
prop; see [Prerendering](#prerendering) below.

## Declare the Website

Declare the site as a module-level const (rather than inline in the
Stack):

```typescript
// alchemy.run.ts
import * as AWS from "@alchemy.run/aws";

export const Website = AWS.Website.SolidStart("Website");
```

`rootDir` is the project root — the directory holding `package.json`
and `vite.config.*`. It defaults to `"."`, so set it only when the app
does not sit next to `alchemy.run.ts`:

```typescript
export const Website = AWS.Website.SolidStart("Website", {
  rootDir: "./app",
});
```

## Add it to the Stack

Yield the site from your Stack and return its URL:

```typescript
// alchemy.run.ts
import * as Alchemy from "alchemy";
import * as Effect from "effect/Effect";

export default Alchemy.Stack(
  "MySolidStartSite",
  {
    providers: AWS.providers(),
    state: AWS.state(),
  },
  Effect.gen(function* () {
    const site = yield* Website;
    return { url: site.url };
  }),
);
```

## Add environment variables

The server function's environment is configured under `env`:

```diff lang="typescript"
// alchemy.run.ts
export const Website = AWS.Website.SolidStart("Website", {
+  env: {
+    API_BASE: "https://api.example.com",
+  },
});
```

`env` values are set on the server on deploy and injected into
the dev server's process environment under `alchemy dev`, so server
code reads the same values in both modes. Sibling props tune the
server itself (`timeout`, `maxConcurrencyPerEnvironment`,
`maxEnvironments`).

An output from another resource only exists once that resource is
yielded, so declare the site inside the Stack generator instead:

```typescript
// alchemy.run.ts
Effect.gen(function* () {
  const api = yield* Api;

  const site = yield* AWS.Website.SolidStart("Website", {
    env: { API_BASE: api.url },
  });

  return { url: site.url };
});
```

## Read the environment in server code

The SolidStart server is a plain Node server, so API routes,
server functions, and SSR read the environment from `process.env`:

```typescript
// src/routes/api/hello.ts
export function GET() {
  return new Response(process.env.API_BASE ?? "unset");
}
```

Values prefixed `VITE_` are inlined into the client bundle at build
time instead, as `import.meta.env.VITE_*` — set those in the shell
that runs `alchemy deploy`, not in `env`.

## Prerendering

Nitro renders the routes you list at build time into `.output/public`.
They are uploaded to S3 and served from the edge with no Lambda
invocation:

```typescript
export const Website = AWS.Website.SolidStart("Website", {
  nitro: { prerender: { routes: ["/", "/about"] } },
});
```

`prerender` takes the routes to render (`routes`) and can crawl links
from prerendered pages to prerender them too (`crawlLinks`). The
`nitro` prop is the home for all nitro options (route rules, storage,
...) — the integration owns the plugin instance, so they cannot live
in `vite.config.ts`. Values must be JSON-serializable; `preset` is
owned by the deploy target, and a foreign preset is a hard error.

## Run on a Lambda Function

Web Functions run in a subset of Regions. Elsewhere, set
`server: "function"`: the app builds with the `/solidstart/aws` deploy target
and runs on a Lambda Function behind a streaming Function URL, tuned with
`memorySize`, `architecture`, and `runtime`:

```diff lang="typescript"
// alchemy.run.ts
export const Website = AWS.Website.SolidStart("Website", {
+  server: "function",
+  memorySize: 2048,
});
```

## Local dev

```sh
bun alchemy dev
```

`alchemy dev` runs SolidStart's own Vite dev server (native HMR)
instead of deploying anything; `site.url` is the dev server's
`http://localhost:<port>` address and no AWS resources are created.
Nitro plays no part in dev. Wrap the site in `Alchemy.remote()` to
deploy the real infrastructure even during dev.

SolidStart's plugin resolves its app root and route directory from
the process working directory, so one `alchemy dev` process serves
one SolidStart app at a time.

:::caution[Run `alchemy dev` under Node]
SolidStart 2's dev server answers requests through `srvx/node`, which
returns the string `[object Object]` instead of the rendered document
when it runs under Bun. Production builds are unaffected — only the
dev server is. Until that upstream gap closes, run `alchemy dev` with
Node (`npx alchemy dev`) for SolidStart projects.
:::

## Custom domain

```typescript
// alchemy.run.ts
export const Website = AWS.Website.SolidStart("Website", {
  domain: { name: "app.example.com" },
});
```

The certificate is created in `us-east-1` (required by CloudFront),
DNS validation records and the alias record are managed through
Route 53. The hosted zone is inferred from the hostname — pass
`hostedZoneId` to pin it when several zones could match.

## Share a distribution with Router

CloudFront distributions take minutes to create. To serve several
sites (or a site plus an API) from one distribution, attach the site
to an [`AWS.Website.Router`](/aws/frontend/static-site#compose-sites-with-a-router):

The site takes the Router's outputs, so both are yielded inside the
Stack generator:

```typescript
// alchemy.run.ts
Effect.gen(function* () {
  const router = yield* AWS.Website.Router("FrontDoor", {
    domain: { name: "example.com" },
  });

  const site = yield* AWS.Website.SolidStart("Website", {
    domain: { router },
  });

  return { url: site.url };
});
```

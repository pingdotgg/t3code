# Useful choices in merged T3 Code descriptions

These descriptions were inspected on 2026-09-05. The examples support the
specific lessons below; merge status does not make every part exemplary or
override current contribution rules. Some hosted media could not be retrieved,
so these observations concern the descriptions and their evidence structure.

| Example                                                                          | Useful choice                                                                                                                                                                                                  |
| -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [#9782 — composer expansion](https://github.com/pingdotgg/t3code/pull/9782)      | A short trigger/cause/result explanation, focused verification, and explicit disclosure that browser verification was skipped at maintainer request.                                                           |
| [#9847 — theme editor](https://github.com/pingdotgg/t3code/pull/9847)            | Repeat save/reopen on base and candidate. Before/after captions explain which color should persist and which value actually appears.                                                                           |
| [#9887 — PR sorting](https://github.com/pingdotgg/t3code/pull/9887)              | Captions identify the concrete smaller/larger PR ordering. The description distinguishes tested sorting from the unverified live branch-update path and unavailable video.                                     |
| [#9860 — progressive usage](https://github.com/pingdotgg/t3code/pull/9860)       | State the shared viewport, data, and pending-environment condition so the comparison tests the claimed loading behavior.                                                                                       |
| [#9876 — mobile usage tabs](https://github.com/pingdotgg/t3code/pull/9876)       | Identify the device and scenario; repeat the round trip and verify retained selections. The untested Android path is explicit.                                                                                 |
| [#9878 — autosave lifecycle](https://github.com/pingdotgg/t3code/pull/9878)      | Separate write-boundary tests, actual disk persistence, and UI observations. Explain why a related issue remains open. Scale detail to the real lifecycle ambiguity.                                           |
| [#9835 — GitHub reads](https://github.com/pingdotgg/t3code/pull/9835)            | Fewer requests did not yield a faster measured reload, so the description avoids that claim. GIFs are labeled as sparse sampled frames and older capture revisions are disclosed.                              |
| [#9768 — Linux process collector](https://github.com/pingdotgg/t3code/pull/9768) | Give comparable timings, units, sample method, workload, and platform. Restrict the conclusion to collector cost rather than app response time.                                                                |
| [#9799 — regression recovery](https://github.com/pingdotgg/t3code/pull/9799)     | Map multiple explicitly combined regressions to their fixes and observed results; group supplementary evidence and disclose simulated inputs and untested paths. This is not a model for making every PR long. |

The common pattern is a checkable argument: the problem, the changed behavior,
the observation that demonstrates it, and the limits of that observation.
Use the current repository template to express that argument at the smallest
useful length. Avoid copying checklists or autogenerated bot summaries merely
because they appear in a merged description.

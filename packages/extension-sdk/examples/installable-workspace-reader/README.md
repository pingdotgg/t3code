# Installable workspace reader package

This directory contains the three files consumed by the trusted environment installer: t3-extension.json, client.mjs and server.mjs. They are already self-contained ESM entries. There are no npm lifecycle scripts, runtime dependencies, private app imports or bundled React. The client uses the React object injected by its host; JSDoc imports are public SDK types only.

The package contributes a project reader view, an explicit composer context selection and one read-only server tool. The view calls example.installed-reader/read through the installed tool bridge. The server handler delegates to the host capability t3.workspace/read-text, using the same input/result contract exported by @t3tools/extension-sdk/workspace. The installer/runtime must supply an independently authorized environment/project grant and the actual workspace read service. A descriptor does not grant itself authority.

Open the view through the host command, enter a relative path, and choose Read file. Successful reads provide the actual text and truncation status. The last successful read for that environment/project/thread and workspace revision is available through Selected workspace text in the composer. Selection is explicit and captures existing read text; it performs no hidden read during Send. Context is capped below 8 KiB and reports truncation; at most 16 scoped last reads are cached in this client factory. Saved view state contains only the path. Restore does not automatically reread or recreate a domain resource. Hidden/disposed views abort pending tool calls and refuse late presentation updates.

The tool may also be delivered by a supported model-tool host. This package alone does not install that transport, implement provider delivery, authenticate scope or enforce canonical filesystem confinement. Those remain host responsibilities. The worker runs trusted code, not a sandbox; readOnly is a declared tool policy, not a security boundary around arbitrary JavaScript.

Focused tests execute the real client/server entries with injected host React and a host adapter reading an actual temporary fixture file. They cover context capture, restoration without reread, environment separation and hidden cancellation. They do not claim a running installed environment or a real provider call; the runtime/app integration must establish those separately.

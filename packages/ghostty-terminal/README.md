# Ghostty web terminal

This package is the browser adapter for the same official `libghostty-vt` C ABI used by Android.
It is intentionally not an xterm compatibility layer. The web client and the terminal extension
both render through it.

- `src/runtime.ts` owns the WebAssembly instance and runtime ABI layouts. `loadGhosttyRuntime`
  takes the WASM bytes from the host and shares one instance per sources object.
- `assets/ghostty-write-pty.wasm` is a 112-byte callback trampoline for terminal-generated PTY
  replies.
- `src/core.ts` owns per-terminal Ghostty handles and translates the C ABI into render snapshots.
- `src/renderer.ts` batches backgrounds and style runs into a Canvas 2D frame.
- `src/surface.ts` owns browser input, IME, selection, scrolling, sizing, links, and cursor
  blinking.
- `assets/SymbolsNerdFontMono-Regular.woff2` is the symbols-only Nerd Font (MIT) the surface
  registers lazily from the `symbolsFontUrl` option, so prompt glyphs render without a locally
  installed Nerd Font.
- `assets/` holds the artifacts, reproducibly generated by `scripts/build-libghostty-wasm.sh`,
  and their notices. The upstream pin and license live once, at `native/libghostty-vt/` at the
  repository root; the wasm embeds the pinned revision in its build info and the ABI test
  verifies it against mobile's `VERSION`. The notice copies in `assets/` are test-checked
  against the same files.

The package never fetches its assets. Each host reads `@t3tools/ghostty-terminal/assets/*` its
own way and passes the bytes and font URL in: the web client through Vite asset URLs, the
terminal extension through package assets. Sources import nothing host-specific, so any bundler
or Node's type stripping can load them.

Keep browser behavior here and terminal transport in the existing client runtime. Do not add React
state to the render loop. Both WASM artifacts are ordinary read-only assets, not executables.
